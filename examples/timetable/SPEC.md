# 课间：朋友共同空闲时间

## 产品与用户

面向同一学校、同一时区的朋友小组，让大家录入每周固定忙碌时段，并快速找出所有选中成员共同空闲的时间。当前替代方式是在聊天中反复发送课表截图，人工比对。

核心价值：在一个小组内，回答“这周哪一天，我们至少能一起空出一小时”。这是待通过试用检验的价值主张，没有市场验证证据。

核心承诺样例：甲在 09:00–10:00 忙碌、乙在 10:30–11:00 忙碌，查询 09:00–12:00、最短 60 分钟，结果只包含 11:00–12:00。反例：某人尚未录完整安排时，不能把缺失数据当作全天空闲。计算规则用 R-004 的确定场景验证；持续维护意愿在试用中观察，不伪称已测得。

已选条件：主目标是找共同空闲；手工录入可接受；所有参与者使用学校当地时间；第一版只处理每周固定安排。忙碌时段可以是课程或其他固定占用，不保存课程名称、老师或地点。

## 范围

### V1

用户建立个人账号，维护每周忙碌时段，创建或加入朋友小组。在明确共享范围后，小组成员可以查看彼此的忙碌时间，并查询共同空闲。一个账号可以加入多个小组。

第一版适用于正在执行的稳定周课表，查询日期限制在未来 7 个自然日内（含当天）；结果按固定周安排推导。

### 不在 V1

学校系统导入、图片识别、单双周或考试周、临时改课、跨时区、日历同步、聊天、自动预约、公开用户搜索、通知和支付。

### 可能的 V2

先观察手工维护是否成为实际障碍，再决定是否调查课表导入。只有试用反馈表明临时变化显著影响结果时，才讨论例外日期。V2 没有承诺日期，也不进入 V1 任务清单。

## 页面与主流程

| 页面 | 主要行为与状态 |
| --- | --- |
| 账号入口 | 创建账号、登录、退出；身份验证失败时提供可理解的错误，不进入私人页面 |
| 我的时间 | 显示、添加、编辑、删除每周忙碌时段；首次使用时区分“尚未提供”与“确认没有固定占用” |
| 小组 | 创建、通过邀请加入、成员列表、查看共享忙碌时段、离开、删除自己创建的小组 |
| 找共同空闲 | 选择参与者、日期、搜索窗口、最短时长；显示结果、缺失资料或无结果 |

主流程：建立账号 → 创建小组或接受邀请 → 阅读共享说明并确认加入 → 录入忙碌时段并标记完整 → 选择成员与日期 → 查询共同空闲 → 线下决定是否约见。

用户进入邀请页面时，先显示小组名称和共享说明。未登录的用户先完成登录，再回到邀请。无效邀请不泄露小组成员或时段。查询结果只表示按录入数据推导的空闲，不代表成员承诺出席。

体验方向（本教学场景的可逆设计假设）：简洁的中文时间协调工具，以日期、参与者和结果为主层级。查询页固定呈现条件与“查询”主动作；结果先显示可用区间，再显示依据和查询时间。我的时间用星期与时间标识区分占用，不能只靠颜色。手机窄屏仍可读完整时间与缺失成员；不依赖插画素材。制作查询界面前，以查询、缺资料和无结果三种状态形成可评审布局样例（T-007），再按实际操作验收。

跨功能情景：已打开结果时有人离组 → 历史画面不保证实时撤回，但下一次读取按当前权限拒绝并清除无权内容；安排修改后重新查询 → 使用当前安排，不能把旧结果标成最新；查询失败 → 保留条件并明确失败，不把缓存结果作为新计算。它们分别由 R-003、R-005 和 T-003、T-005、T-006 覆盖。

## 需求与验收

### R-001 — 个人身份与私人访问（V1）

每个人拥有独立身份和显示名。显示名不作为唯一身份依据，可以重名。登录方式由实施方选择，但必须能验证身份并支持用户在退出后再次登录；不要求非技术用户选择认证供应商。

验收：未登录者无法查看私人课表或小组数据；一个人不能修改另一个人的时间；退出后再访问私人页面需要登录；再次登录同一身份能看到原有数据。验证失败或网络失败不能显示为登录成功。

### R-002 — 维护完整的每周安排（V1）

时段包含星期几、开始时间、结束时间，精确到分钟，范围为同一天的 00:00–24:00，不支持跨午夜。开始必须早于结束。24:00 只允许作为结束。

重叠或相邻的忙碌时段在计算时视为并集；原录入项可独立编辑。首次录入需主动标记“安排已完整”。空表默认不是全天空闲；用户可以明确确认“本周没有固定忙碌时段”。后续编辑保存立即生效；用户也可以将安排标回未完成。

验收：错误时段不能保存，并说明原因；增删改保存成功后重新进入仍一致；保存失败保留本次输入并显示失败；没有完成标记的空表与主动确认空表可区分。

### R-003 — 小组与共享关系（V1）

创建者自动成为成员，最多 10 人（本示例暂用目标，见 A-001）。只有创建者能取得或重新生成邀请链接；旧链接重新生成后立即失效。邀请在小组删除前有效，不提供公开搜索。

加入前说明：成员将共享忙碌时段和完整状态给该小组所有成员，也能看到其他成员的共享信息。本人确认后才加入；不把未加入的人预先暴露给组内。重复接受同一小组邀请不会创建重复成员；满员时不能加入。

任何成员可以离开。创建者若不想保留小组，可删除小组；V1 不支持转让创建者身份，创建者不能通过“离开”留下无主小组。删除只移除小组关系和邀请，不删除各成员自己的时间资料。

验收：无效链接、重复加入、满员和删除后邀请均有确定结果；非成员不能读取小组资料；离开后下一次读取立即拒绝访问，所有仍打开的小组视图在下一次数据刷新时清除无权查看的内容；不能撤回他人之前已见到或自行保存的信息。

### R-004 — 查询共同空闲（V1）

成员选择小组内至少两个人（可以包含自己）、一天、搜索窗口和最短时长。默认选择所有成员，默认窗口为 08:00–22:00，默认时长 60 分钟；用户可修改。窗口必须位于同一天且开始早于结束；时长为正整数分钟，不能长于窗口。

时间按小组固定时区 `Asia/Shanghai` 解释。忙碌区间使用左闭右开边界：09:00–10:00 的忙碌不占用 10:00。将所有选中成员在当天星期对应的忙碌区间合并，从搜索窗口中扣除，输出长度不少于最短时长的最大连续空闲区间，按开始时间排序。结果不拆成固定长度的小格子。

验收场景：窗口 09:00–12:00；甲忙碌 09:00–10:00，乙忙碌 10:30–11:00。最短时长 30 分钟时结果为 10:00–10:30、11:00–12:00；60 分钟时仅为 11:00–12:00。没有足够长的区间时显示无结果，并允许改条件。

缺失安排时，列出尚未标记完整的选中成员，不返回貌似完整的共同空闲。只有一位参与者、非小组成员、无效时间或超出日期范围时阻止查询并说明原因。

### R-005 — 结果与数据变化一致（V1）

查询时读取当前共享数据并标记查询时间。打开的旧结果不保证实时更新，提供“重新查询”操作。若成员离开、组被删除或本人失去访问资格，重新查询时按当前权限处理；不能继续把旧选择当作有效成员。

验收：修改时段后重新查询反映变化；服务不可用时显示“查询失败”，保留筛选条件，不把缓存结果标成最新；结果旁说明“按已录入的固定周安排推导，不含临时改动”。

## 数据与访问

| 数据 | 归属 | 可见与可改范围 |
| --- | --- | --- |
| 个人身份、显示名 | 本人 | 本人修改显示名；组员只见显示名及组内成员身份 |
| 忙碌时段、完整标记 | 本人 | 本人修改；共享小组的成员可读；其他人不可读 |
| 小组、成员关系 | 小组 | 组员可读；加入、离开、删除遵循 R-003 |
| 邀请 | 小组创建者管理 | 创建者取得或更新；持有链接的人可看到加入所需信息，不提前看到课表 |
| 查询结果 | 本次查询 | 按当前组权限读取，不生成公开分享链接 |

V1 不采集课程详情或其他个人档案。不提供完整账号注销流程；退出登录、删除自己的时段、离开或删除小组均可用。账号生命周期扩展需要后续单独定义，不能由实施方悄悄增加数据用途。

## 约束与质量

产品使用中文，支持手机浏览器和桌面浏览器。主要操作可通过键盘完成；忙碌状态除颜色外还须有文字或时间标识。没有经过测试的性能承诺。最多 10 人是产品规模假设，不是负载测试结论。
