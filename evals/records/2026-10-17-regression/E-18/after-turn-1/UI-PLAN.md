# 暖纸色索引档案：界面详细方案

状态：当前界面方案，已在文档中替换 [旧深色方案](UI-PLAN-OLD.md)；尚未实现或验收。
权威边界：本文件拥有视觉与布局细节；[SPEC.md](SPEC.md) 拥有产品规则、稳定需求 ID 和任务状态；[ACCEPTANCE.md](ACCEPTANCE.md) 保存实际证据。本轮仅改文档。

## 1. 方向与阅读顺序

把阅读摘录工具做成可查阅、可对照的纸色档案。用户先在索引找到摘录，再读原文上下文，最后自行确认关系。暖纸色是工作区的基础，不以装饰性纸纹、做旧裂痕或拟物翻页制造阅读噪声。

用户已决定的方向：暖纸色索引档案；固定展示原文与审核动作；替换旧深色方案。用户已澄清：概念稿上的 2030 日期与 0.99 评分仅为画面示意。

保留现有摘录列表、原文对照和关系审核能力。视觉升级不能引入 AI 可信度判断、虚构日期、自动确认关系或新审核业务动作。

## 2. 信息架构与主要界面

宽屏采用三个有明确职责的区域，共同处于一个暖纸色工作区：

| 区域 | 显示内容与主动作 | 布局行为 |
| --- | --- | --- |
| 左侧：摘录索引 | 现有摘录列表、简短摘录内容、真实保存日期或缺失提示、清晰选中状态；沿用已有筛选能力，不为方案新增筛选功能 | 列表独立滚动；选中项保持可辨认；长标题可换行 |
| 中部：原文对照 | 当前来源标识、所选摘录及其上下文、与当前摘录相应的定位或高亮；查看原文是主要阅读动作 | 原文容器固定占据主要视口空间；长正文在容器内滚动；不随详情整体滚出视口 |
| 右侧：关系审核 | 当前关系对象和必要说明、已有审核状态、既有确认动作、操作反馈 | 当前对象在顶部明确标识；说明区可滚动；动作区固定于面板底部且不覆盖说明 |

顶部仅保留现有页面标题、必要导航与简短状态。不给框架、实现进度、版本号等开发信息安排产品展示位。

示意阅读顺序为“摘录索引 → 原文证据 → 用户确认”。关系审核动作保持视觉清晰，但不以大面积强调色压过原文。

## 3. “固定显示”的具体含义

- 固定的是原文阅读区域与审核操作区域，不是把整段长文强行缩小或截断。正文允许滚动，原文区不能被详情滚动推出视口。
- 主工作区在可用窗口高度内布局；索引列表、原文和长说明分别管理必要的溢出。面板标题与操作反馈归属清晰，避免出现无法辨认所属区域的滚动条。
- 审核动作不再位于详情内容末尾。操作区预留实际高度，不用悬浮覆盖正文、末行、焦点或错误提示。
- 切换摘录后，原文、关系对象及动作必须一起对应新对象。新原文尚未就绪时展示明确加载状态，不能拿上一条原文当作当前证据，也不能让动作误作用于上一条关系。
- 保存中防止同一动作重复提交；切换与保存的既有语义应保持一致，结果反馈明确属于哪一条关系，不新增未经要求的批量审核或自动跳转规则。
- 空列表时保留页面结构并显示“暂无摘录”；原文区和审核区显示未选中状态，操作不可用，不展示假数据。

## 4. 窄屏与内容变化

窄屏将索引压缩成顶部的当前条目选择控件，其展开区域不应长久占据审核工作区；选择后收起并返回当前原文。具体控件沿用现有工程可用方式。原文是主体，必要的当前关系摘要靠近原文；审核动作固定在底部的独立区域，两者在审核场景下同时出现。

禁止把原文和审核动作分拆成互斥的页签，或要求用户滚到长详情末尾才能确认。长关系说明可在原文附近的说明区展开、滚动，但不能顶走原文容器或底部动作。

断点按内容是否仍能清晰阅读来决定，不把某个未经验证的像素值当作产品承诺。实施验证应覆盖宽屏三栏、刚好需要折叠索引的中间宽度、窄屏上下布局；检查长中文、长来源标题、较大字号、少量和大量摘录。窗口变化后选中对象和审核状态应保持。

若极小窗口或放大文字导致布局无法容纳，优先减少装饰间距、折叠索引和次要说明，保持文字可读、原文与动作可达；不得以缩小字体、隐藏原文或覆盖内容解决。

## 5. 暖纸色视觉系统

以下具体样式属于**非阻塞设计假设**：由本方案提出，用于让实施有清晰起点；用户选定的是暖纸色索引档案方向，并未确认每个色值或尺寸。实施时可根据真实内容、现有设计系统和可读性结果调整这些细节，不需要为可逆细节增加审批步骤。

| 元素 | 建议起点 | 用途 |
| --- | --- | --- |
| 整体底色 | 暖米纸色 `#F4EFE5` | 统一档案工作区 |
| 原文与内容表面 | 浅纸色 `#FCF8F0` | 给阅读区轻微层次，避免旧版纯白块与暗背景的强烈割裂 |
| 主文字 | 墨褐 `#302B25` | 正文、关系对象、主要标题 |
| 次级文字 | 灰褐 `#6B6258` | 日期、来源、辅助说明；若实测辨认困难则加深 |
| 分隔线 | 浅褐 `#D8CCBC` | 列间边界、索引行边界 |
| 活跃与主动作 | 暗砖红 `#8A4234` | 选中索引标记、已有确认动作的重点；面积克制 |

标题、索引项和正文形成稳定层级。索引用细分隔线和小型档案编号感表达秩序，编号若无真实数据来源只作布局标记，不冒充业务 ID。正文以现有可用、支持中文的字体为基础；可用略有书卷感的标题字形，但不增加字体下载依赖。字重、段落间距、行宽优先保证长文阅读。

采用轻边框、少阴影、适度留白；不使用深色大背景、霓虹状态、仪表盘式评分圆环或大面积纯白编辑卡片。选中、禁用、失败、成功状态同时依靠文字或图形区分，不能只换颜色。

复核这些假设的时机：首次在实际内容上完成宽屏与窄屏排版时。调整标准是正文和状态能辨认、层级清楚、固定区域无冲突，不能以风格一致为由牺牲证据阅读。

## 6. 内容真实性与异常状态

| 状态 | 原文和关系区域 | 审核动作与反馈 |
| --- | --- | --- |
| 正常 | 展示真实保存内容与对应上下文 | 复用已有动作及保存语义 |
| 加载中 | 清楚标为加载，不用概念稿文字充当真实内容 | 依赖该原文的确认暂不可用 |
| 未选中或无摘录 | 提示选择摘录或暂无摘录 | 无可确认对象时不可操作 |
| 原文缺失或失败 | 说明原文不可用，并提供实际可用的重试方式 | 不替用户确认；禁用依赖证据的确认 |
| 保存中或失败 | 保留当前可读证据和关系上下文 | 保存中抑制重复提交；失败清晰说明并可重试，不先显示成功 |
| 保存日期缺失 | 显示“暂无保存日期” | 不以 2030、当天日期或示意数据补值 |

不展示 0.99 或任何可信度/真假评分，也不把它改名为“关系强度”后继续使用。用户自行确认关系是产品规则，概念稿数值不构成性能指标、算法要求或质量门槛。

## 7. 实施边界与验证交接

只改界面表现和审核操作的展示位置，沿用现有数据、可见范围和审核能力。本方案不指定框架、存储、接口或代码文件；实施者应先检查实际工程，不能从此文档推定代码结构。

需覆盖的端到端验证：选中摘录 → 阅读对应原文 → 滚动长文仍能审核 → 用户确认 → 检查真实保存反馈；再检查切换对象、原文失败、保存失败、日期缺失、空列表与窄屏重排。键盘操作时焦点不得进入被遮挡的区域，当前对象和错误信息应可辨认。

验证依据是 SPEC.md 的 R-001/R-002 和 T-001/T-002 完成条件；实际截图、内容样本、操作步骤、结果进入 ACCEPTANCE.md。旧验收只能证明旧方案，本文件完成不代表上述验证已经执行。
