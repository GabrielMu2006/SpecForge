## 1. 产品与核心承诺

面向在 macOS 本机整理中英混合草稿的独立创作者。用户主动加入分散的资料，希望发现哪些内容服务于同一个真实项目，减少逐篇回忆和手工归档的负担。产品提出建议，用户决定是否归入项目。现有整理工具、实际使用频率和市场需求尚未调查，不视为已验证事实。

**核心承诺：完全断网且没有 API Key 时，仍能根据内容含义发现项目关联，包括措辞不同的中英资料；共同出现一个词不足以证明属于同一项目。** 归入项目、主题相似、真实版本继承是三个不同判断，不互相替代。

以下是说明承诺的合成示例，尚不是测试集或效果证据：

| 输入情境 | 有用结果 | 误导或失败结果 |
| --- | --- | --- |
| 中文草稿描述某个创作者访谈项目的提纲，英文笔记用不同措辞记录该项目的同一批采访对象与主题安排 | 即使标题、语言和用词不同，也提出同项目候选，展示可核对的内容依据，等待确认 | 因为缺少共同关键词而完全无法发现关联；仅给出宽泛“都是写作”的解释 |
| 一篇讨论商业模式，另一篇讨论机器学习模型，两者都含“模型” | 保持独立；有疑问可不推荐 | 仅因共享“模型”就建议合并成一个项目 |
| 两篇文章都谈城市生活，但分别服务于两个不同的创作项目 | 用明确项目线索区分；证据不足时保留未归类 | 把相近主题当作同一真实项目 |
| 同一篇稿件的两个版本，与一篇主题相似的独立文章同时出现 | 可分别建议项目关联；只有用户确认真实继承后才建立版本关系 | 将语义相似、时间相邻或文件名相似直接认定为前后版本 |

人工确认是最终控制机制，不能用来掩盖低质量建议。全部不推荐、只能匹配近重复文本、或大量误报都可能使核心承诺不成立。

## 2. 已选 V1 与边界

以下均来自用户已选范围，不因尚未验证而移到 V2：

- macOS 本机应用；用户主动加入 TXT、Markdown、可选中文字的 PDF、公开网页和公开 GitHub 仓库文件。
- 仓库先列可加入的文件，再由用户勾选；不自动导入整个仓库。
- 本机完成中英混合内容的语义归类建议；用户确认后才改变项目归属。
- 项目状态、草稿版本管理、macOS 桌面组件。
- 原文件不改；外部来源保留只读快照。
- 无 Key、完全断网时，本机归类核心流程成立。
- DeepSeek 为默认关闭的可选增强；用户提供自己的 Key。

不在 V1：设备扫描、监控目录或自动抓取新文件；原文件改写、移动和删除；扫描 PDF 的 OCR；私有或需登录来源；账号、云同步、团队协作。没有增加支付、独立分析面板、自动撰写或其他 AI 功能。

V2 尚未承诺；V1 反馈后再讨论，不列入当前任务和验收。

## 3. 建议默认行为与主要场景

本节是用户委托推荐的可逆细节，标记为 **A 类非阻塞假设**，不是用户逐项确认。若后续使用反馈否定，可调整，不改变第 2 节范围。

### 3.1 界面与信息层级（A-001）

采用清晰、偏文本的 macOS 桌面界面。侧栏显示“待整理”和项目；主区域优先显示资料标题、来源及待处理的关联建议；详情区域显示正文与建议依据。视觉方向为系统原生控件、简洁排版、足够对比度，状态同时用文字表达。无需外部图片资产。

关键场景：

- **首次打开 / 待整理**：解释“只处理你主动加入的内容”，主操作是“加入资料”；没有资料时不给虚构推荐。
- **加入预览**：选择来源后展示即将加入的资料、可提取内容和失败项；仓库先看文件列表再勾选。用户可取消，已选择内容不因单项失败消失。
- **建议审阅**：优先展示建议归属的项目、相关资料和可核对的文本片段；提供“确认”“选其他项目”“暂不处理”“不相关”。新项目建议可修改名称后确认。
- **项目详情**：标题与状态在先，随后是已确认资料和草稿版本；待处理建议与确认内容明确分开。
- **来源 / 版本详情**：展示只读内容、来源与快照时间、用户确认的版本关系；可打开可访问的原位置。
- **设置**：本机运行状态、来源管理、DeepSeek 开关与 Key、数据删除说明。
- **桌面组件**：显示用户选定项目的标题和状态；点击进入对应项目。组件不承担归类确认或内容编辑。

设计前置任务 T-003 需明确窄窗口、长标题、中英混排、键盘操作、错误恢复以及组件可容纳的信息。未给定像素尺寸或视觉稿；这些交互通过原型验证后再进入依赖它的界面实现，不另设默认审批流程。

### 3.2 一次完整整理

1. 用户主动选择本地文件或指定公开来源；本地读取权限只覆盖明确选择的内容。
2. 应用预览提取结果；保存应用内只读内容副本及来源记录，原文件保持原样。
3. 本机分析产生候选关联。无足够依据时保留待整理，不强行给每份内容分配项目。
4. 用户核对证据后确认加入已有项目，或确认创建新项目。用户也可直接手动归类。
5. 项目显示确认后的资料；若资料有真实继承关系，用户另外建立或确认版本关系。
6. 用户设置项目状态，在桌面组件中查看并打开该项目。退出、重启和断网后，已保存的确认结果仍存在。

### 3.3 重要组合规则（A-002 至 A-006）

| 当前状态 + 动作 | 结果、保留内容与反馈 |
| --- | --- |
| 有未处理建议，用户确认其中一项 | 只改变用户确认的归属；其他建议保留。后续分析不得覆盖此决定；依赖旧归属的建议标记需重新核对 |
| 用户拒绝某资料与某项目的关联 | 记录此拒绝，避免同一内容对同一项目无变化地重复提示；内容或项目材料变化后才允许重新提出，并说明变化。用户可撤销拒绝 |
| 一份资料可服务多个项目 | 允许用户分别确认多个项目关联；保留同一份内容记录，各项目不互相取得归属决定权；删除一个关联不影响其他关联（A-002） |
| 相似资料已有项目关联，用户建立版本关系 | 项目关联不变；版本关系需要独立确认，不能由相似度代替（A-003） |
| 本地原文件或网页内容变化，用户主动重新加入 | 旧快照不覆盖；内容相同则提示已存在，内容不同则保留新快照供比较，不自动认定新版本或继承旧确认（A-004） |
| 项目从进行中改为已完成 | 仅改变项目状态，不锁定资料、不自动选择“最终稿”、不删除建议。之后仍可手动整理 |
| 项目设为已归档 | 从默认整理候选与默认项目列表中隐藏，内容及版本保留；用户可显式查看、恢复或将资料加入归档项目（A-005） |
| 删除项目 | 说明将移除项目和该项目关联；资料及其版本保留在资料库，其他项目关联不变；不触碰源文件。组件显示项目已移除并引导重新选择 |
| 删除资料 | 先说明将移除应用内副本及涉及的项目关联、建议和版本引用；明确确认后执行。其他版本不删除，原先引用该资料的版本标记“前序已移除”，不虚构跨越继承 |
| 离线时打开已加入的网页或仓库资料 | 读取已有快照；明确这是快照。刷新或加入新远程内容失败时提供重试，不影响既有内容 |
| DeepSeek 请求中关闭增强或断网 | 停止后续发送；已发出的内容无法声称撤回。保留本机结果和人工决定，失败可重试，不自动改成本机以外的其他服务 |
| 建议页切换项目或退出 | 保留待处理项；不把离开视为确认。已提交的确认立即保存；取消正在编辑的项目名称等表单时提示未保存内容（A-006） |

## 4. 需求与可观察验收

所有需求的范围均为 V1，状态为 Planned。功能验收与核心质量验收分开；R-004 的核心证据尚缺，不能据此宣称规格已就绪。

### R-001 — 明确选择本地资料，保留原文件

支持用户主动加入 TXT、Markdown 和可选中文字的 PDF，仅处理选择的文件。选择动作不授权扫描所在目录、关联目录或整台设备。推荐本地文件也保留应用内只读副本，以便移动源文件后仍可整理（A-004）。

验收：断网、无 Key 时，这三类有效文件可进入预览和待整理；中文与英文可正确核对提取内容。扫描件、损坏、无法解码或无可用文本的文件显示具体原因，不伪装成已成功分析。批次中有效项可继续加入；取消未提交导入不创建资料。加入前后原文件内容不变。

### R-002 — 主动加入公开网页和所选仓库文件

联网时由用户明确提供公开 URL。网页只加入指定页面，不遍历站点。GitHub 仓库先展示文件路径与可选状态，再读取勾选文件；不自动取得未勾选文件正文，不跟进子仓库。推荐只允许可提取文本的文件类型，二进制、不可访问及超出可处理能力的项目给出原因（A-007）。

验收：未勾选文件不进入资料库；列表加载或单个文件获取失败可重试，成功项不丢失；需要登录、访问受限或失效的 URL 不绕过限制。断网加入远程内容时解释需联网，已导入资料仍可使用。保存获取时的只读快照、URL、时间；仓库文件还保留路径及可取得的来源修订标识，不把后续远程变化混入旧快照。重定向到需登录或非公开资源时停止该项。

### R-003 — 完全离线仍可运行本机归类

在全新安装、网络被阻断且无 API Key 的条件下，用户应能加入本地资料、得到依含义产生的关联建议并完成确认，同时使用既有项目、版本与组件。必需本机资源应随可分发安装方案到位，不以首次联网下载、登录、远程授权或激活 DeepSeek 为前提。暂未证明这样的方案可分发。

验收：在最终声明支持的最低设备环境，用独立验收资料执行 R-001、R-004、R-005、R-006、R-007、R-008 的离线旅程；记录安装资源、运行环境与网络被阻断证据。能显示资料或手工建项目不能代替本机语义能力；资源缺失必须报错，不能静默退化为只有关键词后宣称达标。质量还必须通过 R-004 的独立评价。

阻塞：B-001、B-002、B-003；对应 T-001、T-002。

### R-004 — 提供有依据的同项目语义建议

基于资料含义与明确项目线索，建议加入已有项目，或将待整理资料作为新项目候选。跨语言、不同措辞的关联属于核心能力；单词重合、相近主题和近重复不得充当全部实现。解释显示真实来源片段与关联线索，不编造背景、项目事实或版本关系。证据不足允许不推荐；可说明信息不足，不展示未经校准的百分比为“真实概率”。

验收分两层：

- 行为：建议始终未确认；每项可追溯到参与分析的资料快照，确认前可查看、拒绝或暂存。没有可用候选时显示待整理空结果，仍允许手动归类。
- 核心质量：按第 6 节，使用独立验收集评价跨语言同项目发现、共享词无关资料、同主题不同项目及版本混淆。保留漏报、误报与弃答；不能用单个简单成功例、训练材料成绩或仅仅可运行的模型作为通过证据。质量门槛尚未采纳，因此此项尚无可宣称达标的数值。

阻塞：B-001、B-002、B-003；对应 T-001、T-002、T-006。

### R-005 — 用户控制项目归属与纠正

建议不直接建立确认项目或归属。用户可确认已有项目、新建命名项目、手动选择项目、拒绝关联、暂不处理、移除关联及撤销最近一次归属操作。采用第 3.3 节的多项目关联和拒绝记录规则（A-002、A-006）。后台分析不得覆盖人工归属。

验收：确认前后状态明确；拒绝后不无变化地反复出现同项建议；暂存与重启后待处理项仍在；撤销恢复操作前的关联。新项目名称相同不会自动合并项目；提交前发现项目已删除时保留资料、提示重选，不创建悬空关联。断网时以上行为成立。

### R-006 — 项目状态清晰且与资料独立

推荐状态为“待开始 / 进行中 / 已完成 / 已归档”，新项目默认待开始（A-005）。用户可手动切换；状态不由加入资料或模型建议自动改变。已完成不等于存在最终稿，已归档不等于删除。

验收：更改状态后重启仍保留，项目列表和详情一致；归档可查找并恢复；归档项目不进入默认自动候选但可显式选择。删除项目按第 3.3 节保留资料及其他关联；组件同时处理状态变更或项目删除。

### R-007 — 保存草稿版本，分别确认真实继承

推荐使用“草稿组 + 不可变版本快照 + 用户确认的前序关系”（A-003）。用户可把资料加入草稿组、命名版本、指定前序版本；允许从同一前序出现多个后续，不强制把独立分支压成单一时间线。关系必须无环，不能以加入时间或相似度自动建立。展示正文和版本标签供核对，不承诺自动合并或生成差异解释。

验收：两份相似文章可以同项目但没有版本关系；用户可确认另一份资料为前序，或明确作为独立草稿；修改版本标签不修改快照；拒绝自引用和循环关系。解除版本关系不删除内容、不改变项目归属。删去前序资料后保留后续内容并标记前序已移除。离线可查看与维护这些关系。

### R-008 — 桌面组件反映本地项目状态

组件显示用户选择的项目及其状态，点击打开应用的对应项目；无项目时引导在应用中选择。推荐组件只读，不显示正文、来源片段或 Key（A-008）。

验收：断网可读取已保存项目状态；应用内修改状态后组件在系统允许的刷新周期内显示更新，不能承诺即时刷新。项目删除或取消选择后不继续显示旧内容为有效项目，提供空状态。系统刷新限制、支持版本和实际延迟需在 T-010 验证并如实说明，当前无实测时延。

### R-009 — DeepSeek 增强默认关闭且可撤回后续发送

关闭或未配置 Key 时，所有本机核心流程可用，不弹出强制配置步骤。用户启用后，仍由用户针对明确选择的内容主动发起增强；发送前预览本次资料、片段和用途，确认后才发送，不因公开来源而自动上传整库。Key 采用系统凭据保护方式保存，不进入资料、组件或日志；允许移除 Key。接口能力、条款及安全保存的具体方案仍待验证。

验收：首次启动和关闭增强时没有模型服务请求；未确认发送前无资料外发。增强结果标明来源，与本机建议一样等待人工确认，不覆盖已确认结果、不自动建立版本关系。Key 无效、额度不足、网络失败时显示原因且保留本机结果；关闭开关阻止后续请求，并明确已发出的内容不能由本机撤回。用待验证的真实接口测试结果证明增强链路，不能只凭占位界面宣称可用。

### R-010 — 应用内资料的访问、删除与恢复边界明确

资料、项目、版本、建议和用户决定均保存在本机，无产品账号或共享访问。外部来源是只读快照；更新通过主动加入产生新快照。移除来源记录与删除应用内资料的区别在操作前说明。推荐提供明确的“清除全部应用资料”动作，单独确认，且不删除原文件（A-009）。

验收：离开详情、重启或源文件不可访问不会丢失已保存快照和归属；相同内容的重复加入提示已存在并可保留新的来源记录，不自动添加项目或版本关系。删除按第 3.3 节执行并更新组件，不留可搜索的旧正文；清除全部数据连同本机派生索引和 Key 一并清除。已发给外部服务的内容不声称随本机删除而被删除。磁盘不足或保存失败时不显示成功、不修改源文件，保留可重试的选择并明确哪些操作未落盘。未要求云备份或跨设备恢复，不能把本机快照宣传为灾备。

### 6.2 代表性材料与判定协议（T-001）

先获得经资料所有者许可的实际或适当脱敏材料，覆盖多个真实项目和独立草稿；材料仅在本机评价，默认不交给增强服务。覆盖中文、英文、中英混排、短笔记与长稿、同项目不同措辞、同主题不同项目、共享词无关内容、近重复及真实版本。不能只用为候选方案量身编写的例子。

由了解项目真实目的的创作者标注“同项目 / 不同项目 / 无法确定”，允许多项目归属。版本另标“存在继承 / 不存在继承 / 无法确定”，记录判断依据；不以文件名和时间自动生成真值。争议和无法确定项保留用于弃答评价，不硬充确定样本。

将开发材料和独立验收材料分开，按真实项目及版本家族隔离，避免同一稿件的近重复内容跨两部分造成虚高成绩。开发部分用于调方案；冻结独立验收部分及标注版本后才进行最终评价。规模和构成先形成清单，足以覆盖上述类别后再定，不在本稿伪称已收集多少份。

以下是**建议采用的评价维度，不是已采纳门槛或测量结果**；最终判定须同时考虑有效发现和错误归并，不能仅凭总平均分：

| 维度 | 定义与计数口径 | 数据与采用状态 | 关联 |

质量倾向建议为“宁可保留待整理，也不强推证据薄弱的归并”，同时必须证明能够发现措辞不同的有效关联。该倾向不能代替 B-002 所需的可接受标准。门槛应在查看独立验收成绩前，由产品负责人结合代表性材料与错误代价采纳；当前委托推荐可逆细节，不等于授权把核心质量标准说成已定。

如后续采用数字目标，必须在此处及相关任务中同步记录：指标定义与单位、计数方法、数据集及版本、建议/已采纳状态、采纳依据和日期。实测结果单列环境、时间及证据，不混写为目标。更换材料或口径时保留旧基线与原因。

### 6.4 本机方案验证（T-002）

可探索的方案方向是本机中英语义表征结合项目线索，生成可解释候选，并与只用关键词或近重复匹配的基线比较。这里只提出方向，没有选定模型、依赖或存储技术，也没有证明它可分发。

验证需检查候选资源与依赖的再分发许可、首次离线安装、无需 Key 和远程激活、中英关联效果，以及最低支持设备上的资源占用与等待体验。离线实际运行必须能区分第 1 节的正反例，并按 T-001 的协议评价；公开演示或模型自报指标不能代替产品材料测试。

最低 macOS 版本、处理器架构、可接受安装体积、内存和等待时间尚未选定（B-003）。先测候选方案、形成可解释的支持范围建议，再由产品负责人确定对核心用户是否可接受；不擅自宣称支持所有 Mac。数字性能结果与可接受目标分别记录。

失败分支：若方案在目标设备、许可或质量上不可行，保持本规格 Draft，提出需要用户选择的替代支持范围或方案；不能删去离线语义承诺、仅靠关键词/人工分类、强制启用 DeepSeek 或把已选功能移到 V2 后称 V1 完成。
