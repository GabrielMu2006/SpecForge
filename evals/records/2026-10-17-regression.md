# SpecForge 0.2.0 剩余行为回归记录

日期：2026-10-17。测试基线：发布提交 `0120f132dc88a9d424408072393b67bc94646258`，运行文件与 v0.2.0 一致。宿主：本次 Codex 桌面会话的 collaboration 子代理；模型标识未独立确认，不据此报告模型名称或跨模型结论。

本轮补跑 15 个剩余编号场景及 E-16 第二阶段，共 17 个独立启动的子代理会话、22 个实际用户/助手回合。E-02 按计划延续 E-01；E-04、E-13、E-17 使用原会话后续消息；E-09、E-15 另开无历史的新会话，仅读取保存的草稿恢复。E-16 第二阶段从上一轮真实产出的方案和未改原型开始。

结论：本轮 16 项场景/阶段在下列 harness 范围内均观察到预期行为，未发现要求修改 skill 运行指令的失败。E-06、E-07 是提示约束模拟；E-01、E-08 的路由检查是给定目录项下的行为观察。结合[首轮 E-11、E-14、E-16 第一阶段](2026-10-17-forward.md)，18 个编号均有实际执行证据，不能称为完整原生宿主端到端通过。

## 方法与证据边界

- 每个独立会话只接收当前用户消息、所需原始文件和可读取的完整 skill。评分预期、历史复盘及其他案例未提供，指令禁止读取；隔离通过独立临时工作区和访问范围指令实现，并非操作系统沙箱。
- 文件均为合成输入。运行产物先保存，再由主评估者读取实际响应与文档、比较文件差异和哈希、人工计数问题；没有从预期答案重建对话，也没有改写评估产物使其“通过”。
- 每个目录保留 `before/`、每轮 `after-turn-N/` 快照及其清单、`turn-N.request.txt` 和实际返回的 `turn-N.response.txt`。响应文本从 collaboration 返回消息逐字归档，统一保留末尾换行；这是用户可见响应，不是完整原生工具调用轨迹。E-16 另有浏览器运行原始输出、检查脚本、JSON 和截图。
- Git 不保存空目录；空输入由 manifest 中的 `input_sha256: {}` 表示，空产物由对应轮次 JSON 的 `files: {}` 表示。检出后可按清单创建空工作区，不在原始证据里添加占位文件。
- E-06 的“不可联网”和 E-07 的“文本任务不能用文件工具”由 harness 指令约束，工具没有从宿主实际移除。E-07 先读取包含内联完整 skill 的启动材料，之后要求文本交付；文件快照为空。它只能证明约束下的回答，不能证明真实无工具宿主兼容。
- 问题均通过普通文本返回，后续答案由预先给定用户消息发送，没有调用真实异步问题卡。因此文件恢复已测，原生异步保存、预选项、迟到回答和 UI 中断恢复未测。
- E-01/E-08 提供可发现 skill 的目录项但没有显式调用；观察输出是否进入产品发现或直接修复代码。没有记录原生选择器完整调用轨迹，不能由此证明自动发现或加载在所有宿主上正确。

证据入口：[运行清单及 SHA-256](2026-10-17-regression/manifest.json)。所有下列“通过”只指一次所列运行及这些边界，不是稳定通过率。

## E-16 浏览器证据与审核

原始 HTML 从 234 字节变为具有列表、详情与返回行为的原型。实际浏览器通过本地 HTTP 运行；记录保留原始 [Playwright 输出](2026-10-17-regression/E-16-phase2/after-turn-1/output/playwright/results.txt)、[33 项 JSON](2026-10-17-regression/E-16-phase2/after-turn-1/output/playwright/results.json)、[检查函数](2026-10-17-regression/E-16-phase2/after-turn-1/output/playwright/checks.js)及 10 张 PNG。

主评估者读取了检查函数和结果，并另外查看了[1440px 混合列表](2026-10-17-regression/E-16-phase2/after-turn-1/output/playwright/mixed-1440.png)与[375px 长文本详情](2026-10-17-regression/E-16-phase2/after-turn-1/output/playwright/detail-375.png)。列表主次与入口清晰、长标题未挤压操作；详情全文连续可读。返回位置与焦点、三组视口、空态及其他行为由实际脚本结果支持；这次主审核没有再次操作浏览器。

200% 检查是 CSS `zoom: 2` 模拟，不能替代浏览器原生缩放和辅助技术验证。脚本中绝对路径与端口属于原始运行证据，跨目录复跑时须在工作副本中改写输出路径和地址；不要改动归档原件。测试集通过浏览器响应替换注入，正式单件藏品未被测试数据污染。临时服务与一次性工具缓存已由运行者清理。

## 修复、维护校验及尚需人工验证

没有观察到需修复的 SpecForge 行为失败，因此未修改运行指令或版本、也未基于单次成功增加规则。补充了评测方法对模拟工具约束、目录项路由和文本恢复的限制说明，保存本轮证据并更新评测入口。原始运行产物保持原样。

仍需人工或真实宿主环境验证：

1. **原生异步提问卡**：仅提交一题、等待迟到回答、关闭/重开会话、请求重发，确认未答项仍在且预选/超时不成为答案。
2. **真正关闭工具与原生选择器**：在确实没有浏览或文件工具的宿主重跑 E-06/E-07；通过真实 skill 目录发现重跑 E-01/E-08，核对技能是否加载以及是否误触发。
3. **真实会话与不同宿主/模型**：本次只是新子代理读取草稿，没有退出/重启 Codex，也没有验证 Claude Code、其他模型或长期多轮稳定性。模型标识需由可核对记录确定。
4. **产品视觉与辅助功能**：E-16 的 Safari/Firefox、浏览器菜单 200% 缩放、屏幕阅读器、真实触控设备及用户对收藏感的判断；截图和 Chromium 几何测试不能替代这些检查。
5. **真实产品能力**：学校接入、AI 质量、Widget、经营游戏平衡与玩家体验没有在这些合成规格回归中实现或验证。

37 项维护工具测试、skill 格式校验、仓库链接/示例图校验及打包通过。额外对 8 份最终 SPEC 和 E-07 文本稿运行结构检查；E-16 的状态单元格包含证据说明，超出可选 lint 的规范子集，依赖图由主评估者核对，未冒充直接 lint 通过。证据组装首次校验在清单尚未生成时发现 manifest 链接缺失；补齐清单后复验通过，首次输出也保留在 verification 目录。

维护校验和证据完整性结果随附在 manifest 的 `verification` 中；静态通过不替代上面的行为观察和人工事项。发布包运行文件与已有 0.2.0 相同，新增记录不进入 skill ZIP。
